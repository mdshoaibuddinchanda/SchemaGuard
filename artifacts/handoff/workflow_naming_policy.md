# Workflow Naming Policy

SchemaGuard uses descriptive, responsibility-based names for operational files,
folders, identifiers, and generated evidence. Execution order is recorded only in
the roadmap and handoff stage fields.

* Completed repository work: smoke-data foundation and grouped-split correction.
* Operational compatibility work: model runtime compatibility gate.
* Master-plan correspondence: environment compatibility.
* Future work: acquisition and validation of the remaining SchemaOrbit-14 datasets.
* Scientific identifiers remain unchanged: dataset IDs, seeds, model IDs, view IDs,
  metric names, split strategies, package versions, checkpoint names, and schema versions.
* Existing numbered paths were migrated with history-preserving renames and reference
  validation; compatibility copies were not retained.

No scientific configuration was changed by this naming decision.
